How it looks

Overview

If you use the [Herdr app](https://herdr.dev) (the desktop client of herdr-core), Hivemill can live inside it: - **A status bar** across the bottom of the window. It shows each project's open PRs and last merge, one segment per team (`Lenovo factory 3 live`: the machine's name, its role tag, the live agents), what needs you, Claude weekly usage, cost per merged PR and today's spend, and on the right the most urgent alert. Clicking it opens the dashboard. - **A dashboard tab** with these cards: - **Alerts:** only what needs a person. - **Budget & cost:** the Claude 7-day and 5-hour usage against the factory's caps, and the Cursor plan state. It also shows spend per day and per org, cost per merged PR (median, p90 and average, with time to merge), and the most expensive tasks. - **Resources:** every machine of your setup. That is this computer and each `hc machine ls` machine, with each team's machine tagged `factory`; if no `hc` link reaches a team, its row comes from that team's API. For each machine: reachable or not, OS and CPUs, uptime, agents running there, and memory, load, disk and swap. Below that: the spawn gate and merges per day. A machine that cannot be reached, or one low on disk (under 20 GB or 5% free), raises an alert. - **One card per project:** its open PRs, oldest first, and its recent merges. - **One card per team**, titled by the team's machine (see [Machines and teams](#machines-and-teams)): its boss and lanes, what needs you, active goals, agents, and shipped work. ![The dashboard's factory card: lanes and tiles](film/herdr/panel-factory.png) ![The status bar across the bottom of the app](film/herdr/panel-status-bar.png) The app's own agents list already shows every agent on this machine, so the dashboard does not repeat it. An agent appears on the dashboard only in an alert, for example when its context window is almost full. New alerts also appear as notifications. Clicking one opens the dashboard. This is a Herdr app mod: JavaScript the app runs natively. It is not a web view. The factory's web UI ([web-ui.md](web-ui.md)) stays as it is, and the dashboard reads the same JSON API (`/api/home.json`, `resources.json`, `throughput.json`, `tokens.json`).

Install

Run this on the machine where you use the Herdr app. That can be your laptop rather than the factory's box. Open the app once first. ```sh python3 plugins/hivemill/scripts/install.py --herdr-app --dry-run # show the plan python3 plugins/hivemill/scripts/install.py --herdr-app --yes ``` It changes three things and nothing else: | Path | What | |---|---| | `~/.config/herdr-app/mods/hivemill/` | the mod (`main.js`, `data.js`, `mod.json`), copied from `plugins/hivemill/herdr-app/mods/hivemill/` | | `~/.config/herdr-app/layouts/hivemill.json` | a copy of the app's `main` layout, with its status bar replaced by the Hivemill bar | | `~/.config/hivemill/dashboard.json` | the settings below. A re-run changes only the fields you pass and keeps your projects. | When the app is running, the installer then switches it to the Hivemill layout. `--no-sidebar` hides the sidebar in that layout, for a machine kept for screenshots; a re-run keeps whichever you pass. `ctrl-shift-l` switches layouts, so you can go back to Herdr's own at any time. To uninstall, delete the first two paths. A re-run updates the mod and regenerates `hivemill.json` from the app's current `main` layout. Make your own layout changes in a separate copy. Exit codes: - `0`: done, with a last line of `RESULT PASS herdr-app ...`. - `2`: a usage error. - `3`: the Herdr app is not set up on this machine. - `1`: a step failed, with a last line of `RESULT FAIL step=herdr-app-<step>`.

Where the factory is

This is the single-team setup, with one factory. For more than one team, see [Machines and teams](#machines-and-teams). The factory's web UI listens on `127.0.0.1:8765` of the factory's box by default ([SETUP.md](SETUP.md)). Pick one of these: | Your setup | Flags | |---|---| | The app runs on the factory's box | none: the default `http://127.0.0.1:8765` | | The factory's box is an `hc` machine in the app (`hc machine ls`) | `--factory-machine NAME`. The dashboard asks the factory from that machine, so no port is opened. | | The factory's UI is reachable on your network | `--factory-url http://HOST:8765` | `--factory-web-url URL` is the address your browser uses for the dashboard's "Open" links. It defaults to the factory URL when no machine is set.

Claude, Cursor or both

A factory has two orgs, `claude` and `cursor` ([`scout/orgs.py`](../scout/orgs.py)). Most installs run one of them. With `"orgs": "auto"` (the default), the dashboard shows an org only while it has a live boss or director, goals or agents: - Claude budget meters and Claude usage alerts appear only when `claude` is shown. - The Cursor plan row and the "Cursor tasks unpriced" note appear only when `cursor` is shown. - Lanes, needs, goals and agents are filtered to the orgs shown. Lanes appear only when more than one org is shown. To fix the choice, pass `--orgs claude`, `--orgs cursor` or `--orgs claude,cursor`. `--orgs auto` goes back to automatic.

How it works

- One copy of the mod at a time does the polling, using a short lease in the app's shared state. Every copy reads the same data. The bar and the tab never poll twice. - The polling intervals: factory home every 45 s, resources every minute, cost every 5 minutes, project PRs every 2 minutes, and agent screens every 2 minutes (`hc read <t> --lines 30`: this computer's agents and the agents of project spaces). - The mod's data layer has node tests: `node --test plugins/hivemill/herdr-app/tests/*.test.mjs` (with node 24 the files must be named; a directory does not work). `tests/test_herdr_app_dashboard.py` runs them when node is installed. - `herdr-app check ~/.config/herdr-app/mods/hivemill` loads the mod once and reports errors.

Relation to G-031

G-031 SC8 asks how herdr-core hosts a view. T-1392 and T-1420 found that `hc` has no view slot, and that is still true: herdr-core draws nothing. There is a slot one layer up, in the Herdr app. Its mods (`~/.config/herdr-app/mods/<name>/`) are panels, tabs and bars that the app draws, and they read `hc` through the app's `hc()` and `exec()`. This dashboard is one working example of that slot. Whether it settles SC8 is for that goal's own spec to decide.

Limits

- The factory reports today's spend, spend per day, cost per merged PR, merges per day and the most expensive tasks for all orgs together. When only one org is shown, the Budget card says so. - The Cursor CLI reports no token counts, so Cursor work is unpriced (see [web-ui.md](web-ui.md)). - The status bar replaces Herdr's own status bar in the Hivemill layout. It keeps where you are, the branch and the commands hint, but not the agent count, which the agents list shows.

# Hivemill dashboard in the Herdr app

If you use the [Herdr app](https://herdr.dev) (the desktop client of herdr-core), Hivemill can live inside it:

- **A status bar** across the bottom of the window. It shows each project's open PRs and last merge, one segment per team (`Lenovo factory 3 live`: the machine's name, its role tag, the live agents), what needs you, Claude weekly usage, cost per merged PR and today's spend, and on the right the most urgent alert. Clicking it opens the dashboard.
- **A dashboard tab** with these cards:
  - **Alerts:** only what needs a person.
  - **Budget & cost:** the Claude 7-day and 5-hour usage against the factory's caps, and the Cursor plan state. It also shows spend per day and per org, cost per merged PR (median, p90 and average, with time to merge), and the most expensive tasks.
  - **Resources:** every machine of your setup. That is this computer and each `hc machine ls` machine, with each team's machine tagged `factory`; if no `hc` link reaches a team, its row comes from that team's API. For each machine: reachable or not, OS and CPUs, uptime, agents running there, and memory, load, disk and swap. Below that: the spawn gate and merges per day. A machine that cannot be reached, or one low on disk (under 20 GB or 5% free), raises an alert.
  - **One card per project:** its open PRs, oldest first, and its recent merges.
  - **One card per team**, titled by the team's machine (see [Machines and teams](#machines-and-teams)): its boss and lanes, what needs you, active goals, agents, and shipped work.

![The dashboard's factory card: lanes and tiles](film/herdr/panel-factory.png)
![The status bar across the bottom of the app](film/herdr/panel-status-bar.png)

The app's own agents list already shows every agent on this machine, so the dashboard does not repeat it. An agent appears on the dashboard only in an alert, for example when its context window is almost full.

New alerts also appear as notifications. Clicking one opens the dashboard.

This is a Herdr app mod: JavaScript the app runs natively. It is not a web view. The factory's web UI ([web-ui.md](web-ui.md)) stays as it is, and the dashboard reads the same JSON API (`/api/home.json`, `resources.json`, `throughput.json`, `tokens.json`).

## Install

Run this on the machine where you use the Herdr app. That can be your laptop rather than the factory's box. Open the app once first.

```sh
python3 plugins/hivemill/scripts/install.py --herdr-app --dry-run   # show the plan
python3 plugins/hivemill/scripts/install.py --herdr-app --yes
```

It changes three things and nothing else:

| Path | What |
|---|---|
| `~/.config/herdr-app/mods/hivemill/` | the mod (`main.js`, `data.js`, `mod.json`), copied from `plugins/hivemill/herdr-app/mods/hivemill/` |
| `~/.config/herdr-app/layouts/hivemill.json` | a copy of the app's `main` layout, with its status bar replaced by the Hivemill bar |
| `~/.config/hivemill/dashboard.json` | the settings below. A re-run changes only the fields you pass and keeps your projects. |

When the app is running, the installer then switches it to the Hivemill layout. `--no-sidebar` hides the sidebar in that layout, for a machine kept for screenshots; a re-run keeps whichever you pass. `ctrl-shift-l` switches layouts, so you can go back to Herdr's own at any time. To uninstall, delete the first two paths.

A re-run updates the mod and regenerates `hivemill.json` from the app's current `main` layout. Make your own layout changes in a separate copy.

Exit codes:

- `0`: done, with a last line of `RESULT PASS herdr-app ...`.
- `2`: a usage error.
- `3`: the Herdr app is not set up on this machine.
- `1`: a step failed, with a last line of `RESULT FAIL step=herdr-app-<step>`.

### Projects

A project is a repository whose agents run in this Herdr app (for example a team you run beside the factory):

```json
{ "name": "My app", "github": "OWNER/NAME", "space": "my-app",
  "wait_patterns": [{ "match": "NEEDS REVIEW", "clear": "REVIEWED", "label": "waits for a review", "after_min": 15 }] }
```

- `github`: the repository whose open and recently merged PRs get a card and a segment in the bar. This uses `gh`, logged in on this machine.
- `space`: the Herdr space (id or name) that holds the project's agents. Its tab is where the dashboard tab opens first. A space on an `hc` machine is written `machine/space`, for example `macmini/teamb` (the space named or with id `teamb` on machine `macmini`). An unprefixed name means this computer's space; if this computer has none of that name and exactly one remote space has, that one is used.
- `boss`: for a team that runs no Hivemill API. The exact name of the project's boss terminal, or `{"match": "<regex>"}`. See [Machines and teams](#machines-and-teams).
- `wait_patterns`: text on an agent's screen that means it is waiting on a person. An idle agent showing `match` (and not `clear`) for `after_min` minutes raises an alert, for example a team that asks for a shared resource and waits for a go.

### Demo mode: screens for docs and films

To take pictures you can publish, add this to the settings:

```json
"demo": { "enabled": true, "hide": ["a private word", "another"], "alerts": true }
```

- Task, goal and PR numbers are removed from every title. Agent names lose their task suffix, and the bar says "This computer" instead of a machine name.
- Any row whose text contains a `hide` word is left out: needs, goals, tasks, agents, shipped work, alerts and projects. `"swap"` in `hide` also leaves out the swap meter.
- `"alerts": false` shows no alerts at all.

Turn it off again after the pictures. The Herdr app draws only while its window is on screen, so bring it forward before `herdr-app shot`.
